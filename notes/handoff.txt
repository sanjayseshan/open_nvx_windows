## Corruption root cause and fix

Nine was built without `HAVE_FUNC_ATTRIBUTE_PACKED`, while the Mesa ICD used it. Consequently `enum mesa_prim` was 4 bytes in Nine and 1 byte in the ICD; `pipe_draw_info.index_size` was at offset 4 vs offset 2. Equal overall struct sizes concealed the ABI mismatch, and indexed draws were read with the wrong fields. Cross-compiled layout probes confirmed the mismatch and the corrected layout. The .26 user visual pass confirms the fix on hardware.

- `build_d3d9_nine.sh` loads `patches/mesa9x/nvx-nine-build.mk`, forces the packed-enum define, and invalidates cached generated objects when ABI flags change.
- `mesa_patches/nine/mesa99.c` has compile-time ABI assertions.
- `patches/mesa9x/0007-xp-crt-failure-termination.patch` keeps the clean Nine rebuild XP-compatible; the apply script handles nested winpthreads.
- `patches/mesa9x/0005-nine-draw-range-trace.patch` and `0006-nine-draw-range-metadata.patch` are external Nine diagnostics and are applied by `test/apply_mesa9x_25_patches.sh`.

## Performance status

The .26 live counters show a sustained high volume of small submissions: roughly 4,000 batches per 4,096-sample interval, with about 37,600 TSC cycles per miniport submit IOCTL; stream validation averages ~10,500 cycles and buffer lookup ~1,160 cycles per batch. About 0.82 timed fence waits and 5.7 poll iterations per batch are recorded. These counters show per-submit CPU overhead and frequent synchronization, but do not measure GPU utilization or the game’s frame time directly. The scene is correct; the remaining performance cause is not yet isolated.

Next: let 3DMark finish and record its score/game FPS. Then profile a short repeat with diagnostic logging disabled and compare time spent in Nine/user-mode translation, miniport validation, and GPU fence/presentation. Do not infer GPU saturation from successful batch completion alone.

## Test and build

Always use `NVX_AUTO_RETRY=1` for VFIO tests. Current run command:

`NVX_AUTO_RETRY=1 NVX_RUN_3DMARK=1 NVX_D3D9_BACKEND=nine NVX_NINE_DEBUG=1 NVX_NINE_ONLY=0 ./test/test_full_driver.sh`

Patches must remain in the root-owned `patches/` and `mesa_patches/` directories so a fresh clone can reproduce submodule builds. Current version: 4.0.0.26.
