## Profiling follow-up in progress

- The .30 log already has useful counters: validation is about 34.2B cycles, submit IOCTL about 1.88B, buffer lookup about 1.09B, and pending waits about 0.70B across the session. These are cumulative session totals, not game-only frame costs.
- Added miniport counters to split NVC0 packet/address validation from object-binding validation, plus cumulative buffer-reference and relocation totals. These will appear in the next build's `NVC0-PERF` and 4096-submit `NVC0-PERF-SAMPLE` records.
- Existing `NOUVEAU_COALESCE_PROFILE` is from the WGL bridge and must not be attributed to the Nine/3DMark path. Miniport process-ID and per-submit samples are the current source for Nine kick/dword/reference behavior.
- No validation, ownership, or fence checks have been removed. Optimize after the next profile identifies which validation stage dominates. Buffer lookup and fence waiting already have counters; the previous totals alone do not justify changing their correctness-sensitive behavior.

## CPU and submission evidence

- QEMU `info cpus` maps guest CPU 2 to host thread 76937 and CPU 5 to 76940. Recent samples show CPU 2 using nearly a full host core and CPU 5 also busy; aggregate vCPU work is roughly two or more host cores. Other vCPUs often sample at the XP idle `HLT` instruction.
- The miniport log reports `RealAddDevice=fffffadfa97430e0`. The XP-specific VideoPort offset used in `src_driver/nvxmp.c` derives `videoprt.sys` base `fffffadfa971b000`; the successful `VpIsMultiFunctionSupported` patch at base+`0x25ad0` confirms that base calculation. Sampled RIP `fffffadfa974fd83` is at offset `0x33d83` in that image. This identifies the module area, not the exact function; a matching XP symbol map is still needed. RIPs `fffff8000081043a` and `fffff97fff0d2357` also recur, but are not symbol-resolved yet.
- The PC sidecar spans boot and the full session, not only each timed 3DMark scene. Its 1,168 idle samples and active RIP counts cannot be treated as a game-only profile. The most common active address is `fffff8000081043a` (137 samples); VideoPort RIPs are much less frequent. Resolve module bases and sample only while the benchmark process is active before selecting a function to optimize.
- At the latest serial sample, there were 815,104 submitted batches and 813,954 completed (1,150 pending), with zero submit failures. The queue is not persistently far behind, though this snapshot alone cannot rule out transient stalls.
- Cumulative miniport counters at that point: validation 34.2 billion cycles, submit 1.88 billion, buffer lookup 1.09 billion, pending-wait 0.70 billion; fence polls about 14.4 million across 773,776 calls. Kernel-side measured work is not enough to explain all host vCPU use, so user-mode Nine/Mesa/app cost and VideoPort/graphics-kernel dispatch remain candidates. Do not claim a specific hot function without symbols or a profiler.
- Coalescing/fence/shim timing callbacks are WGL-bridge instrumentation; the 3DMark/Nine log has no `NOUVEAU_COALESCE_PROFILE` samples. Add equivalent counters at the Nine/miniport boundary before drawing conclusions about step 4–7 costs in D3D9.
- WGL trace records are buffered and dumped after calls, not printed for every frame. The PC sampler now normalizes host-thread CPU against the measured wall interval rather than assuming every sample interval is exactly two seconds. Register snapshots are still samples, not a profile, and monitor queries may perturb timing slightly.

## Performance plan

1. **Push-buffer write cost:** write-combined MDL alias and per-submit copy timing are implemented; current counters show copy cost is not the dominant measured miniport term.
2. **NVC0 barrier behavior:** removed the custom GM107+ VBO barrier patch from the active patch series; retain upstream Mesa behavior.
3. **Nine submission threading:** threaded submit is enabled; CSMT remains gated by persistent coherent mapping, which NVC0 does not advertise.
4. **Batch coalescing:** implemented experimentally in patch 0048. Verify actual Nine kick reduction and image correctness with counters emitted from the Nine path.
5. **Validation cost:** counters exist in the miniport. Add per-stage/per-method attribution and avoid repeating expensive allocation lookups where safe; continue validating submitted command streams.
6. **Buffer lookup:** counters exist. Add a bounded client/GPU-VA lookup structure only if lookup remains material after step 5.
7. **Lock scope:** WGL shim timing exists but is not yet reported for the 3DMark Nine path. Measure the Nine path before changing lock ownership.
8. **Async completion:** normal submissions remain asynchronous; preserve waits required for reuse, readback, and teardown.
9. **Diagnostic overhead:** quiet/diagnostic run modes are prepared. Compare identical benchmarks with driver per-call logs disabled and aggregate counters retained.

## Next actions

1. Map the loaded XP `ntoskrnl`, `videoprt`, `win32k`, and display/miniport image bases to symbols, then resolve repeated RIPs from the sidecar. Do not use the repository's `src_driver/videoprt.sys` as the XP symbol image; it is a separate build and too small for the hard-coded XP offset.
2. Add low-overhead Nine-side counters for draws, push-buffer kicks, dwords/refs per kick, fence polls/waits, and CPU time per frame. Current WGL bridge profiles do not cover 3DMark's Nine execution path.
3. Compare kicks/submissions per frame with the prior build and verify patch 0048 coalesces meaningfully. If VideoPort dispatch dominates, reduce miniport escape frequency through a safe shared submission queue rather than relaxing validation.
4. Retest geometry and score after each submission change. 10k+ 3DMarks is a target, not a result or guaranteed consequence of these changes.
