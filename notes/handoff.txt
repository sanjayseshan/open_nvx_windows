# NVX handoff — 2026-11-23

## Current state

The Mesa migration is on branch `v4.0.0.x`. Both Mesa consumers now target 25.1.6:

- Top-level `mesa` is pinned to Mesa 25.1.6 commit `357bbc55bd419dae5625a14ffa0acf1818f9ebbe` (`mesa/VERSION` = `25.1.6`).
- Gallium Nine uses `submodules/mesa9x/mesa-25.1.x` (`VERSION` = `25.1.6`); `build_d3d9_nine.sh` explicitly selects that tree. Mesa 23.1.9 remains bundled for legacy experiments but is no longer selected by the Nine build.
- Mesa XP/WGL patches are external in `mesa_patches/mesa25/` and `test/mesa25_patch_series.txt`. Mesa9x's XP compatibility patch and Nine overlays are external in `patches/mesa9x/` and `mesa_patches/nine/`.
- Legacy Mesa 23–27 ABI bridge patches were removed from the active path. The WGL bridge and winsys compile against Mesa 25 APIs.

## Build verification

Completed successfully on 2026-11-23:

- `NVX_MESA_ARCH=x64 JOBS=4 ./test/build_mesa_xp64.sh` produced `dist_full/nvxogl64.dll` and `dist_full/nvxmesa.dll`.
- `NVX_MESA_ARCH=x86 JOBS=4 ./test/build_mesa_xp64.sh` produced `dist_full/nvxogl32.dll`.
- `./build_d3d9_nine.sh` produced `dist_full/x86/d3d9.dll`, exports `Direct3DCreate9` and `Direct3DCreate9Ex`, and reports Mesa 25.1.6 in its build manifest.
- The Mesa ICD imports are limited to GDI32, KERNEL32, msvcrt, and USER32. Nine additionally imports ADVAPI32. Full XP export compatibility audit still needs XP system DLL export tables.

This proves the x86/x64 binaries compile and have the expected architecture/entry points. It does **not** prove that either Nouveau WGL or Nine renders correctly in the XP guest. The v4.0.0.2 VFIO run completed, but hardware rendering failed: x64 WGL and Nine used softpipe; x86 WGL used GDI Generic. See test_logs/v4.0.0.2-20261123-121854.log. `dist_full/x86/d3d9.dll` is currently Gallium Nine; building WineD3D afterward overwrites it.

## Latest hardware verification: v4.0.0.4

- v4.0.0.2 used softpipe (x64 WGL/Nine) and GDI Generic (x86 WGL).
- Fixed Mesa25 patch 0007: NVX drmGetVersion returns zero deliberately; XP now validates descriptor registration instead of rejecting the transport with the upstream Linux DRM >= 1.3.1 check.
- Fixed gears preload to select nvxogl32.dll for x86, nvxogl64.dll for x64. The x86 registry already correctly named nvxogl32.dll.
- v4.0.0.3 created NV170 screens in both architectures but rendering caused RM 3D-Z KIND violations, then completion fence timeouts. Subsequent batch IOCTL 0x15 is ERROR_NOT_READY after clientFault=1. Archived failure: test_logs/v4.0.0.3-20261123-123027.log.
- Removed obsolete 0024 depth-kind-zero override from active Mesa25 series. Current miniport supports requested PTE kinds; retain Nouveau's uncompressed depth kind instead of forcing zero.
- v4.0.0.4: x64 gears NV170, 355 frames / 6s = 59.167 FPS; x86 gears NV170, 357 frames / 6s = 59.500 FPS. x64 cube completed 300 frames, OPENGL_RESULT RENDERED, GPU batches and GPU scanout presentation confirmed. x86 cube completed 300 frames at 45.2 FPS. Nine reports Mesa Nine (NV170), creates a HAL device, passes clear/draw readback proof, and renders 60 frames at 57.1 FPS. No KIND violations, fence timeouts or failed batch IOCTLs observed. Log: test_logs/v4.0.0.4-20261123-123322.log.
- Both architectures rebuilt successfully, package XP import audits and host tests passed. Use NVX_AUTO_RETRY=1 for all VFIO tests.
