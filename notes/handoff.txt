# Current status — 2026-11-26, Win98 SE / Gallium Nine

## Latest code and test

- `src_win98/shim/nvx_mdl_win98.c` now mirrors XP's MDL backing model using
  Win98 VMM services: `_PageAllocate` reserves fixed system pages without
  requiring physical contiguity, `_CopyPageTable` supplies the actual PTEs,
  and the driver passes the derived PFNs to the shared GART mapper. Freeing
  releases the VMM block with `_PageFree`. This replaces the old common-buffer
  allocation and fabricated sequential PFNs.
- Win98 VxD/package build passed. The updated driver and one-shot 3DMark03
  runner were installed in `win98_small.img`.
- Test command: `NVX_AUTO_RETRY=1 ./test/run_vfio_win98_autoretry.sh`.
  Current log: `test_logs/win98-20261126-161004.log` (`vm_serial.log`). The
  VM remains running with 3DMark03 open.
- Evidence: `NVX [GART-MDL]` reports a real 17-page PFN list; there are no
  `MmAllocatePagesForMdl failed` or `GART-BACKING-PRESSURE` entries in this
  run. The Nine HAL triangle test completes 60 frames and receives GPU fence
  completion. 3DMark03 produces NVC0 draw submissions and no logged channel
  fault. The user still sees the top-left of the game loading scene flash,
  then a black display. Thus the backing-allocation failure is fixed, but it
  was not the only cause of the 3DMark presentation failure.
- Route still needs proof: the runner writes D9Switcher `nineforce` settings,
  but the 3-second process module snapshot does not list `mesa99.dll` or
  `wined9.dll`. It lists `WINED3D.DLL`; the D9Switcher log is dumped only when
  3DMark exits. Capture a debug run's DLL-load events (or capture the switcher
  log when the process exits) before concluding the benchmark is on Nine.

4. Keep the XP path as reference: `src_driver/nvx_mdl.c` allocates locked

   per-process user mapping remains intentionally disabled because Win98
   stages IOCTL data instead of exposing a kernel VA to ring 3.
