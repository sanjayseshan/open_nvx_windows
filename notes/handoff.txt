# Handoff — 2026-11-18

## Current status: version 3.0.0.328
- Real RTX 3070 VFIO run completed; VM is shut down.
- Driver, Mesa ICD, host/mock suite, and guest 2D/3D checks built and ran. Basic OpenGL cube reached 59.5 FPS; WGL gears reached 61.2 FPS in one run (a later run measured 54 FPS). D3D9 sample reached 61.9 FPS.
- 3DMark05 started through the hardware Nouveau/NVC0 path (`GL_RENDERER NV170`) and submitted about 234,717 batches. It did not complete: the GPU stopped retiring the final fence and RM reported shader program header errors followed by a graphics channel RC fault.
- This is a reproduced GPU command/shader fault, not evidence of VRAM exhaustion. The timeout log reported no MMU fault.

## 3DMark fault evidence
- Last per-client sample: 234,717 submitted / 234,689 completed batches; 28 outstanding. The fence wait counters accumulated about 82 seconds across the run; the final wait hit the 5-second timeout.
- Timed-out global fence: `0x3E2DB`, channel `0x61000405`.
- RM then reported Shader Program Header errors 1, 2, 9, 11, and 18, ESR `0x405840=0xa2040a06`, `0x405848=0x80000000`, and channel RC fault (`engine=1`, `chid=0xA`, `type=0xD`). Subsequent pushbuf rejects are post-fault.
- `.328` keeps the last four accepted NVC0 batches with referenced BO IDs/addresses/sizes and command excerpts. Large batches are truncated to the first and last 256 dwords, so the capture does not yet retain the full shader/program payload; exact offending method/state is not identified.
- 3DMark stdout/stderr did not provide a trustworthy FPS result. The guest was doing substantial work, but the current counters alone do not establish the main performance bottleneck.

## Next work
1. Improve the fault capture to preserve the complete offending batch or safely capture shader/program BO contents and decoded method packets for the timed-out fence.
2. Compare the captured program/header setup and submission ordering with Nouveau upstream, then fix the first concrete mismatch.
3. Rerun one 3DMark test with serial logging and the existing Enter-key automation; verify fence retirement and absence of RM graphics exceptions before judging performance.
