# NVX handoff — 2026-11-24

## Current status

- XP x86 hardware acceleration is now confirmed on version **4.0.0.44**. The offline image is `winxp_x32.qcow2`; its 3DMark05 installer is staged at the All Users desktop and in `C:\test_accel`.
- The XP x86 test run passed 2D fills/blits, native OpenGL (`GL_RENDERER=NV170`), Gallium Nine D3D9 (`Mesa Nine (NV170)`), and the bounded 3D ABI suite. Proof log: `test_logs/xp_v2_20261124-140119.log`; extracted app log: `test_logs/xp_v2_20261124-140119-guest.log`.
- Measured in that run: WGL gears **61.2 FPS**, Nine cube **77.8 FPS**. GPU solid fills/copies and completed NVC0 GPU fences appear in the serial log. The test includes no 640x480x4-bpp mode request; it used 1280x1080x32 primary and 1920x1440x32 secondary modes.
- A targeted x86 serial DDI trace run at `.43` identified and verified the fix: `SET_CURRENT_MODE` preceded `MAP_VIDEO_MEMORY`, but the x86 driver rejected the mode when the first scanout commit found no framebuffer mapping. `src_driver/nvxmp.c` now defers that first commit until `MAP_VIDEO_MEMORY`, where the framebuffer is available. The `.44` release-style run passed with DDI serial tracing disabled by default.
- One subtest remains limited: the optional direct native NVC0 clear packet is rejected (`NVX_NVC0_NATIVE_CLEAR_RESULT FAIL`); the overall 3D suite passes, OpenGL and Nine identify the hardware renderer, and both submit/fence paths are active. Triangle capability is intentionally not advertised in the client ABI test.
- The x64 `.39` benchmark log remains `test_logs/v4.0.0.39-20261124-123907.log`. `vm_serial.log` has been restored to that x64 log. No VM is currently running.

## Build, install, and test x86

```sh
./test/install_xp32_driver_and_tests.sh
NVX_AUTO_RETRY=1 MAX_RETRIES=10 BOOT_TIMEOUT=50 ./test/run_vfio_xp32_autoretry.sh
```

The installer builds XP x86 miniport/display drivers, Mesa Nouveau WGL ICD, Gallium Nine D3D9, and test binaries; updates `winxp_x32.qcow2`; and stages Antigravity tests plus the 3DMark05 installer. `NVX_DISP_SERIAL_DIAGNOSTIC=1` opts into extra display-DDI serial traces. The VFIO test runner shuts the guest down after the desktop test suite; it does not run 3DMark automatically.

## Relevant code

- `src_driver/nvxmp.c` — deferred x86 scanout commit in `IOCTL_VIDEO_SET_CURRENT_MODE`; framebuffer map then initializes native display channels.
- `src_driver/nvx_disp_rpc.c` — native scanout setup and display-channel initialization.
- `src_disp/enable.c`, `src_disp/opengl.c` — XP x86 display DDI and OpenGL pixel-format callbacks.
- `test/install_xp32_driver_and_tests.sh` — x86 builds, image deployment, OpenGL ICD registration, and test staging.
- `test/run_vfio_xp32_autoretry.sh` — real-hardware x86 test runner.
- `mesa_patches/mesa25/0001-nvx-wgl-native-nouveau.patch`, `mesa_patches/nvx_wgl_bridge.c` — WGL to Nouveau/NVX path.
- `mesa_patches/nine/mesa99.c`, `mesa_patches/nvx_d3d9_entry.c` — Gallium Nine D3D9 entry and screen setup.

Keep this handoff as the latest concise snapshot. Bump the minor version for each new test build and preserve the `vm_serial.log` symlink target when running the x86 image.
