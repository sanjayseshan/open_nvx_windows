# NVX handoff — 2026-11-24

## Current status

- RTX 3070 GA104 is the only hardware validated so far.
- Windows XP x64 has the mature OpenGL/Nouveau path. Native XP x86 Gallium Nine has completed 3DMark05; latest user-reported score was 5,409. The x86 release installer still needs a clean-package install validation.
- Win98 SE now has a runtime-proven first hardware 2D path: 32bpp GDI solid fills reach the GA104 copy engine through the 16-bit display driver's BitBlt callback, a Win98 VxD PM shim, and the shared XP miniport/OpenRM/GSP submission.
- Win98 hardware run `test_logs/win98-20261124-214215.log` booted successfully and remains running. It shows 1920x1080x32, `DibEngine=0`, PM API connected, and 32 validated fill rectangles. The miniport emits each success record only after all row submissions complete. Guest `C:\NVXFILL.LOG` contains `START`/`PAINT` from the GDI fill probe.
- Leave the VM running for physical monitor inspection. The six-color probe and desktop rendering need visual confirmation; serial confirms command completion, not pixel color correctness.
- Win98 supports only the accelerated solid-fill case currently. Other GDI operations use CPU fallback; application OpenGL/Direct3D acceleration is not connected.

## Win98 path and constraints

```text
Win98 GDI solid fill
  -> nvx.drv BitBlt -> VxD PM API -> NVX.VXD DIOC
  -> shared HwStartIO -> OpenRM/GSP -> AMPERE_DMA_COPY_B -> scanout VRAM
  -> synchronized driver shadow
```

- `DibEngine=0` is necessary: DIBENG draws into its own DIB shadow and bypasses our display driver's BitBlt callback.
- The private development PM service ID `0x7d00` is currently used to connect the 16-bit driver to the VxD. Do not distribute this build until the ID is assigned collision-free.
- GPU writes use the existing shared `NvxGspSubmitFill` helper and wait for its completion fence. No GPU packet construction was added to the Win98 driver.
- Primary output is currently 1920x1080; synthetic primary 2560x1440 caused stripes and remains disabled. The separate optional head-1 path is not part of this single-monitor test.
- SYSTEM.INI updater must retain exactly `[boot] mouse.drv=mouse.drv` and `[386Enh] mouse=*vmouse`; cursor still needs visual confirmation.
- Win98 GART user mapping remains fail-closed. Do not expose kernel mappings to application processes. A future Mesa/Nouveau ICD needs a safe Win9x mapping or validated shared-ring design.

## Next steps

1. Ask user to visually confirm the physical screen and color-fill probe; do not stop the VM before then.
2. Add a deterministic readback/pixel validation for the GDI fill probe.
3. Replace PM ID `0x7d00` with a registered/collision-free identifier before distributing.
4. Profile synchronous per-row fence waits; batch validated fills through a VxD-owned queue while preserving synchronization and CPU fallback.
5. Add SRCCOPY only after format, pitch, overlap, shadow, and fallback behavior are covered by tests.
6. Keep DirectDraw 3D capability flags honest. Win98 OpenGL/D3D remains future work; reuse Mesa9x/Nouveau and the current NVX VxD transport rather than adding a parallel GPU command encoder.
